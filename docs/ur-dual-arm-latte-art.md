# UR 双臂螺旋拉花（本地仿真）

2026-09-11：首版采用两台 UR10e 的标称标准 DH 参数和简化几何模型。来源：[UR 官方 DH 表](https://www.universal-robots.com/developer/hardware-and-motion/robot-motion-dh-parameters/)。长度单位为米，场景 Y 轴向上；安装位置、夹爪和奶泡杯为本项目工作站配置，不是厂家标定数据或官方 CAD。

## 使用

- 打开终端的 `robot-scene.html`，默认选择「UR 双臂拉花拿铁」。可以播放、暂停、拖动进度、复位，使用「拉花特写」检查壶嘴、奶流和花型。终端与云端订单的三维弹窗也提供该视角。
- 终端技术控制台 → 制作配方 → 选择热饮 → 花型「螺旋」→「添加拉花步骤」→ 检查 JSON → 保存。按钮将原加奶步骤拆出 20 ml，配方版本递增；保存仍走原有后端校验，不会直接执行机械臂。
- `coffee-bot-003/recipes/latte.json` 已作为可执行示例更新到 2.1.0：160 ml 鲜奶 + 20 ml 拉花，总奶量 180 ml。其他饮品不自动添加。

也可以在配方 JSON 中手动加入下列独立步骤，并从原加奶量中扣除相应的奶量。必须放在萃取之后、封盖和出杯之前；拉花之后不可继续加原料。

```json
{
  "id": "latte-art",
  "name": "螺旋拉花",
  "durationSeconds": 30,
  "robotActions": ["latte-art"],
  "latteArt": {"patternId": "spiral", "patternVersion": "1.0.0"},
  "customizationRole": "milk",
  "dispenseChannel": "foam-pitcher",
  "consumes": [{"materialId": "milk", "amount": 20, "unit": "ml"}]
}
```

首版要求配方 optionSchema.temperature 为 HOT，配置 milk 定制选项，仅允许一次拉花，不支持含冰饮品。未知花型、版本、缺失剂量和小于 24 秒的步骤（含随机时长下限）在目录校验时拒绝。30 秒/20 ml 是示例仿真配置，不是实机工艺参数。选择 milk=NONE 时，加奶与拉花同时移除，库存、报价摘要、编译指纹与冻结执行计划沿用现有链路。

## 动作与回放

左臂通过交接托盘取得饮料，持杯到公共工作区；右臂抓住奶泡杯把手、抬起、对准液面、倾斜、沿螺旋倾倒、回正收流、归还奶泡杯，随后饮料继续封盖/出杯。

花型定义在杯子局部液面坐标中，由一个函数同时生成壶嘴位置、奶流落点和泡沫线。右臂的目标姿态补偿把手抓取点、杯体旋转与壶嘴偏移。六关节使用完整位置/四元数姿态 IK；时间线预计算连续关节种子，回放、跳转和重新连接不依赖上一渲染帧的求解分支。视觉子动作在设备提供的步骤时长内展开，不额外改变订单生产时间。

两端投影白名单保留花型 ID/版本，编译指纹冻结配方；网页不执行任意配方脚本。拉花失败即使套用了可重试故障档案，也不会进入 RETRY_WAIT，避免重复倾倒。现有恢复核查机制继续生效。

## 验证与边界

- 全流程采样验证 TCP 位置/姿态、关节连续性、杯子与奶泡杯交接无瞬移、壶嘴与奶流落点一致、完成后归位、回放重置。
- 螺旋演示以 100 ms 间隔进行连杆胶囊近似检查（每段半径 60 mm）及台面高度检查。它不等于完整工位网格碰撞、连续碰撞检测或机器人安全认证。
- 机械臂几何是按 DH 轴与尺寸绘制的简化模型；无真实 UR 控制指令、速度/加速度约束、负载/力矩计算、奇异点裕量验收和出厂标定。
- 奶泡杯目前假设已装有预制奶泡；尚未实现自动打奶泡、补液、清洗和卫生状态机。真实流量随倾角变化以及奶泡在咖啡中的流体扩散尚未仿真，螺旋是可重复的视觉轨迹。
- 旧饮品的设备步骤可能很短，视觉会按其权威时长压缩；这些时间预算不能直接用作实体 UR 运动程序。接实机前需要重新规划时序并校准工艺。

构建与同步：在模拟器仓库运行 `npm run sync:cloud-scene`。测试：模拟器 `npm test`、`.venv/bin/python -m pytest tests -q`；云端 Python/Node 回归沿用原命令。浏览器验证使用现有 Playwright/Chromium，不新增依赖。

## 左臂水平侧夹调整（2026-09-11）

原末端沿世界坐标竖直向下，腕部与夹爪遮挡杯口。现将左臂的工具 +Y 轴设为从底座朝目标的水平方向，工具 +Z 保持竖直；夹指从杯身两侧闭合，腕部留在杯侧。搬运全程使用同一侧夹关系，不在持杯过程中突然翻转夹爪。

为避开侧夹姿态下底座附近的不可达区域，左底座移至 `[-0.62, 0.96, -0.08]`，热水工位 X 移至 `-0.10`，回位先退出到前方走廊。左臂初始关节分支重新检查；右臂奶泡杯抓取方式保持原配置。

杯子在抓取时保存相对工具的旋转，搬运只改变水平朝向，杯口始终向上，放下与换臂时保留杯体朝向。螺旋的杯内局部坐标同时映射到世界坐标，使实际奶流落点与旋转后的花纹仍重合。

本次回归：模拟器 Node 43 项、云端 Node 81 项通过。新增杯体不倾斜、左端水平接近、腕部位于杯侧、交接旋转连续性检查；原全流程 TCP、关节连续性、连杆胶囊与台面采样检查继续通过。Playwright 检查终端演示与云端订单弹窗，1280×900 / 390×900 的拉花特写、播放、跳转、复位及关闭正常；无应用 JS 异常，软件 WebGL 截图的 ReadPixels 性能警告仍属测试环境。截图：`/tmp/ur-side-grip-1280.png`、`/tmp/ur-side-grip-390.png`。本次未改动 Python 业务链路，不将上一轮 Python 数量作为本轮重跑结果。

## 双臂咖啡杯侧夹与交接进退修复（2026-09-11）

右臂在交接、鲜奶、糖浆、封盖和出杯过程中统一使用水平侧夹，杯口保持向上。奶泡杯仍使用原把手抓取和倾倒姿态。右臂只在空手待机位切换工具姿态，采用连续关节插值，避免跨越腕部奇异姿态时突然切换求解分支。

交接穿模的根因是空夹爪直接从上方/斜向进入杯身，或松爪后未退出就向其他方向回位。两种时间线（独立演示及订单步骤）现共享以下进退规则：

- 取杯：移动到杯身侧面的预备位，对准后沿夹持轴水平进入，再闭合夹爪。
- 放杯：放稳、完全张开夹爪、沿夹持轴后退 160 mm；清出杯身后再抬升、转向和回位。
- 空夹爪接近和退出过程中保持工具朝向不变。侧夹搬运线路如穿过底座内侧不可达区，增加绕行点；订单子动作继续按设备权威步骤时长分配，不额外增加生产时长。

本轮验证：终端 Node 47 项、云端 Node 81 项通过。新增两套完整流程（螺旋拉花、香草拿铁）的双臂水平抓姿、沿轴进退和旋转不变检查；按 25 ms 采样，使用夹指/夹掌包围盒与杯体最大半径圆柱检查空夹爪穿模，覆盖拉花前后的右臂放杯、左臂取杯/放杯以及封盖取回。原 TCP、杯体交接连续性、奶流轨迹和双臂连杆/台面检查继续通过。它仍不是完整实体工作站的连续碰撞认证。

Playwright 在 1280×900、390×900 检查鲜奶、糖浆、封盖抓杯、拉花前右臂退出/左臂进入、拉花后左臂退出、回放与复位，均无应用 JS 异常。云端冻结计划三维弹窗也通过；软件 WebGL 截图出现的 ReadPixels 性能警告不影响画面。临时截图为 `/tmp/ur-both-grip-{检查点}-{1280,390}.png`，其中 `left-release-after-art` 展示拉花后的沿轴退出。此次没有修改配方库存/订单后端，不重复宣称 Python 回归或实机验证。
