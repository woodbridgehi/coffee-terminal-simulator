# 联调台与实验室共享工作台配置

## 使用方式

1. 在虚拟设备联调台配置设备位置、工艺、库存、夹爪和传感器，点击保存。
2. 点击页面上的「用当前配置打开实验室」。实验室读取同一服务的配置快照，显示来源、配置标识与读取时间，建立一个全新的独立实验。
3. 运行、暂停、单步、比较策略、导出实验及回放。
4. 联调台参数改变后，在实验室暂停并点击「从联调台载入并重置实验」。不会运行中自动覆盖参数。

共享是**复制配置**，不复制关节当前姿态、持物、剩余库存、故障、命令或仿真时钟。实验从配置的初始状态开始。加载实验室不会改变联调台会话；两个窗口之后独立运行。

推荐启动 `npm run twin:serve`，通过同一服务访问：

- `http://127.0.0.1:9131/device-lab.html`
- `http://127.0.0.1:9131/digital-twin.html?source=device-lab`

独立静态服务 `npm run start:twin` 的 9120 端口没有设备 API，不能直接读取另一端口的配置。可在联调台导出设备配置 JSON，然后在实验室「导入场景／联调台配置 JSON」加载，无需服务在线。此类设备配置按当前内置工作台基准生成布局；完整实验导出则保存已解析场景。

## 哪些参数生效

| 参数 | 实验室中的行为 |
|---|---|
| 安装父对象、位置与旋转 | 同步精细模型、工作点、机器人底座/工具和碰撞代理 |
| 机器人关节限制 | 用于轨迹规划及运动约束 |
| 工艺时间、预热、恢复、出料量与原料消耗 | 用于流程执行和物料账本 |
| 杯/盖初始库存与材料初始库存 | 新实验从初始量开始，实际动作成功时扣减 |
| 夹爪初始开口、上限、开合速度与负载 | 抓取先开合再附着，释放先张开；尺寸/负载不兼容会失败 |
| 抓取/释放基础时间 | 与夹爪所需行程耗时取较大值 |
| 杯垫启用、半径、高度容差及传感器延迟 | 独立仿真中计算与显示，轨迹记录可回放 |

HTTP 确认延迟、命令启动等待、丢通知、断连、独立复位/清洗操作和通信重试仍在联调台验证。实验室沿用任务图调度和自己的速度/策略选择，不承诺与 HTTP 示例规划器得到相同节拍。没有新增自由流程编排器。

## 数据与接口

`GET /api/experiment-config` 是只读接口，返回已解析场景及：

- `sharedDeviceConfig`：完整设备配置副本。
- `configurationSource`：来源、源 sessionId、安装版本、导出时间，以及对场景/配置计算的 SHA-256 标识。

返回数据不含实时命令和现场状态。实验室导出文件保存上述配置、实际任务、状态轨迹和传感器结果；无需再次连接联调台即可回放。共享场景的默认拿铁有 32 步，新增真实落杯及扣库存；原内置场景继续采用原 31 步任务，旧 v1 配置保持兼容。

命令行重算实验仍使用：

```sh
npm run twin:run -- --replay /绝对路径/experiment.json
```

共享实验使用独立的仿真适配层，不发送设备命令，也不修改原设备联调运行时。完整配置快照保留解析后的布局；导入原始设备配置文件时会通过统一配置校验重新生成场景。错误文件或接口不可用时显示原因，不悄悄切换为默认共享配置。

## 验证边界

验证了参数复制、配置深拷贝、只读加载、标识随配置变化、32 步制饮、夹爪动作与附着顺序、杯垫状态、实验导出与确定性重算，以及浏览器的共享加载/运行中阻止替换/回放/窄屏布局。当前仍使用原离散碰撞代理及直立搬运规划；配置加载成功不等于任意布局的整杯流程必然可达。

### 跨运行环境的浮点边界

同一 Node 环境内，共享实验导出后重新计算可严格得到 `deterministic=true`。本轮浏览器导出的实验在 Node 中重算，完成状态、32 步结果、耗时及物料一致，但部分关节角/物体位姿存在约 10^-15 的浮点差异，现有逐值严格比较因此返回 `deterministic=false`、退出码 1。没有放宽比较或把差异当作严格通过；按文件保存的轨迹回放不受此问题影响。跨浏览器/Node 的逐位确定性尚未保证。
