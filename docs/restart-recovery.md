# 制作中断与人工核验

适用版本：2026-09-12。本次需要同时更新终端程序与 coffee-cloud-mvp 服务端、商户前端；没有数据库结构迁移。当前已运行的终端须退出并重新启动才能加载新的 Python 处理入口。

## 现场处理

1. 制作过程中退出、断电或出现本地状态保存异常后，终端显示“制作中断，请联系工作人员”。在线仅表示通信正常，不代表可以接单。
2. 工作人员点击“工作人员 · 人工核验”，查看任务编号、调试/订单类型、发现时间、中断步骤和原因。
3. 现场移除制作区与取杯位的杯子，清理工作区，确认机械臂及工具可安全复位；勾选全部确认项。
4. 点击“核验完成，取消任务并返回待机”。该操作取消旧任务，不恢复制作、不把订单标记为成功、不退回已经消耗的物料；仅释放未消耗的库存预占。真实订单继续沿用云端取消事件与退款处理流程，退款到账需核对后台。
5. 可以选择“稍后处理”或关闭弹窗，任务继续保持保护状态。

本入口通过原生终端桥接调用 `confirm_recovery(task_id, revision, checks)`，不增加公共 HTTP 控制接口。它是现场操作确认，不是员工登录认证系统，也不驱动真实机械臂自动复位。任务编号与版本必须仍匹配，三个确认值必须严格为 true。持久化失败将整体回滚，保留保护状态；普通 cancel/resume/retry/skip 不能绕过核验。

## 后台与同步

- 商户首页告警、设备列表“待人工处理”标记、设备详情均显示异常，调试任务不依赖顾客订单记录，也不受 LIVE/TEST 报表日期过滤隐藏。
- 告警字段：`taskId`、`taskKind`、`occurredAt`（核验需求发现时间）、`stepName`、`reason`、`code`。这不是断电精确时间，也不能据此证明某个动作已经物理完成。
- 新终端通过 HTTP 心跳、MQTT 心跳及 retained state 上报 `recovery` 摘要；每次重启递增任务版本，首次发现时间保持不变。旧任务尽量从仍保留的本地恢复事件找回时间。
- 云端兼容旧设备的 UNKNOWN 制作指令，从租户权限范围内的指令状态记录补充告警。旧数据没有记录的步骤/时间明确显示“未记录”或“—”，不会推测物理状态。更新并重启终端后会补充当前步骤。
- 核验后保留本地已取消任务及 `recoveryReview`，包含检查项、现场操作来源、时间与原异常摘要；`task.cancelled` 进入可靠事件队列。云端处理取消事件并收到正常设备状态后，告警自动解除，商户页面按原刷新周期更新。离线期间云端告警暂留。
- 告警使用已有租户/门店授权及指令行级权限，不向商户开放全局设备事件表。没有新增跨商户查询权限。

## 本次验证与边界

设备运行时 24 项、云端生产一致性/商户设备/遥测测试 48 项通过，使用独立本机 PostgreSQL；验证了旧调试任务告警、首页聚合、跨租户不可见、核验后解除、重复/过期请求拒绝、存储失败回滚。浏览器测试使用隔离模拟数据，不执行现有设备的核验。
