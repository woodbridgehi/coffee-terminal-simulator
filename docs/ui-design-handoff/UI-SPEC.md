# 当前 UI 布局、交互与设计评审要求

基线与范围见 README。本文件中的“现状”来自当前 HTML/CSS 与功能说明；“建议评审”是待设计项，不表示已实现。

## 1. 联调台的现有布局

桌面：品牌栏 → 标题/实验室入口 → 通知条 → 双列工作区 → 页脚。

| 区域 | 现状内容 | 用户要回答的问题 |
|---|---|---|
| 顶部 | Coffee Terminal / QARM、服务连接提示、实验室跳转 | 我在哪个工具？当前能否通信？ |
| 左上工作台 | 时钟、推进、视角、碰撞显示、三维场景、杯槽与取杯 | 命令是否表现为设备动作？杯子在哪里？ |
| 右侧设备区 | 11 个设备卡片、选中名称、状态、定位、传感器 | 我正在操作谁？设备能否接受动作？ |
| 右侧四个标签 | 发命令、设备配置、异常模拟、库存/会话 | 我正在控制动作还是修改参数？ |
| 左侧中部 | 一键场景、预期结果、进度 | 如何验证完整流程和异常恢复？ |
| 左侧下部 | 命令表、单条查询、原因/下一步、原始 JSON/事件 | 接收到命令是否等于成功？失败怎么处理？ |

桌面容器最大 1600 px，左右 32 px 留白、20 px 间距，右列 400 px；≤1150 px 右列 360 px；≤900 px 顺序变为场景→设备操作→一键场景→记录；≤540 px 进一步收窄留白。场景高度随断点约 470/390/420/320 px。设备卡片三列、普通配置字段两列、安装字段三列。高度固定不代表真实三维画布必须保持这些尺寸。

### 操作面板

- 发命令：动作、命令 ID、新 ID 按钮；参数/期限折叠；发送、取消、设备复位；本条反馈与记录跳转。
- 设备配置：简单数值字段；父安装点与位置/旋转；原点开关、恢复默认；高级 JSON 折叠；保存与独立结果提示。草稿与已保存状态需要清楚区分。
- 异常模拟：故障/断连/重连/丢确认/丢通知；强制传感器 JSON；说明“通信中断不一定停止动作”。
- 库存/会话：补料目标、数量单位；配置导入/导出；重置实验及其清空范围。

## 2. 实验室的现有布局

页头 → 左侧工具栏/三维/运行状态/时间线 + 右侧纵向控制卡片 → 页脚。

| 区域 | 内容 | 重点 |
|---|---|---|
| 工具栏 | 开始/暂停、单步、重置、速度、视角、工位/碰撞开关、仿真秒 | 运行、暂停和回放模式应明显区分 |
| 场景/状态 | 当前动作标签、完成任务数 | 停止原因与当前阶段要可见 |
| 时间线 | 任务行、设备/左臂/右臂颜色、已执行区间 | 当前多为技术 ID，设计可评估中文名与详情 |
| 配置卡 | 来源、快照、载入并重置 | 复制配置，不同步运行状态 |
| 设备物料卡 | 设备状态、库存、容器质量/归属、检测状态 | 过程观察不能只剩数字列表 |
| 实验控制卡 | 串并行、比较、导出、故障、复位、补料 | 比较结论需要解释同输入条件 |
| 回放卡 | 导入场景/配置、导入实验、回放滑块 | 配置文件与实验记录不能混淆 |
| 事件日志 | 技术事件 | 保留诊断入口，但避免淹没任务结果 |

右列默认 310 px，≤1000 px 为 265 px，≤720 px 堆叠到主场景下方。场景当前高度约 590/500/410 px；时间线内部滚动，高度上限 320 px。实验室没有联调台那套完整品牌导航和四标签组织，这是**当前差异**，不是要求长期保持。

## 3. 状态语义：改版不能丢失

| 情况 | 必须表达 | 不可误导 |
|---|---|---|
| 加载/未连接 | 数据尚不可用、连接位置 | 显示零库存或设备正常 |
| 已接收/等待 | 已接收，等待资源/前置条件/时钟 | 等同完成动作 |
| 执行中 | 动作、设备、进度/时间 | 允许不加说明地重置或反复触发 |
| 成功 | 已有最终结果，命令 ID 可查询 | 丢通知就当失败再发新动作 |
| 失败/拒绝/过期/取消 | 分别说明原因与恢复步骤 | 所有问题只写“失败” |
| 手动时钟暂停 | 需要推进仿真时间 | 页面卡住或按钮无响应 |
| 保存失败 | 输入草稿、校验原因、旧配置仍有效 | 显示“已保存”却只改了表单 |
| 运行中重载配置 | 先暂停并说明重置范围 | 暗中覆盖正在运行的实验 |
| 传感器强制值 | 报告值被覆盖 | 真实杯子已生成/消失 |
| 回放 | 历史轨迹与记录版本 | 正在操作联调台设备 |

## 4. 建议设计工具优先评审（不是既定实现）

1. **核心动作可发现性**：设备选择、当前设备、发送反馈、场景定位如何形成明确闭环？命令结果是否离发送操作太远？
2. **双工具心智模型**：配置共享入口、来源/版本、更新提醒如何让用户理解“两套独立运行”？
3. **信息密度与优先级**：右侧设备列表和配置面板很长，是否需要可折叠区域/设备分组/详情抽屉？优先给线框方案，勿直接删除诊断功能。
4. **表单与草稿**：单位靠近字段；边界校验、未保存状态、保存成功/失败有对应位置；复杂 JSON 能否逐步转为结构化编辑（需额外实现，单独标注）。
5. **状态可读性**：命令、设备、流程、通信、仿真时钟是不同状态层，不能用同一个“运行中”混写。
6. **危险操作层级**：设备复位、整轮重置、导入并重置要区分作用范围；可讨论确认/撤销设计，但不要在本次原型里暗示已经实现撤销。
7. **场景和时间线联动**：定位设备、定位任务、显示命令关联能否改善观察？鼠标选安装点/拖动设备目前未实现，必须作为新增能力估算。
8. **品牌与可访问性**：统一字体、表面、按钮层级和状态标签；对比度、焦点、Tab 顺序、触控尺寸与非颜色状态提示需要实测。

## 5. 建议设计稿状态与验收清单

- 1440×1000 桌面、1024×768 中屏、390×844 窄屏；无页面级横向溢出，表格可局部横向滚动。
- 展示至少：初始空态、正在连接、选中落杯器、选中夹爪、修改配置未保存、字段错误、保存成功、命令等待/执行/成功/失败、断连、实验完成、配置更新提示、回放模式。
- 两条完整操作故事：① 选设备→发落杯→观察→查询结果；② 改设备配置→保存→载入实验→运行→查看时间线→导出/回放。
- 同 ID 查询恢复、不自动重试非幂等动作、手动时钟、库存恢复范围、夹爪先张开后接近等语义不变。
- 所有可交互组件有默认/悬停/焦点/选中/禁用/错误态；不能只在高保真首页展示成功态。
- 三维区域需保留足够观察面积；说明窄屏是否仅查看还是允许完整编辑，不擅自隐藏关键错误。
- 区分“一轮实验的完成任务数”“一条命令结果”“一杯成品状态”，不将三者合成单个进度。

## 6. 范例覆盖与真实性

两个范例使用实际页面结构和样式快照，加上独立 mock.js。样例会简化日志、任务行数与参数列表，不穷举所有接口状态。场景图片来自本项目修复后的真实实验回放；图片固定，切换示例状态不会产生对应三维动作。实验比较数字来自基线默认独立 31 步实验（串行 347.92 s / 并行 299.82 s），不能当成当前共享参数的运行结果。

顶部新增状态选择只供评审快速看成功/故障/断连反馈，不是现有产品功能。将这些范例交给设计工具时，请同时提交 README，避免将 mock 操作识别为已经实现的后端能力。
