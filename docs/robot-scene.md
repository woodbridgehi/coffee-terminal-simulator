# 双臂咖啡三维工作站

模拟器默认保留二维界面，点击左下角“查看三维制作”可打开与当前任务同步的三维弹窗，关闭即返回二维。手机订单状态页也提供“观看三维制作”入口。独立演示页面仍可用于场景调试。

## 真实任务接入

正常启动现有模拟器即可使用，无需启动额外的三维服务。三维资源随应用离线打包，只有打开弹窗时才加载。弹窗支持透视、俯视、正视与触控缩放，关闭会释放渲染资源。

- Python 接单后，根据冻结的本地配方、实际步骤耗时和物料定义生成 `stepPlan[].visual`，随任务保存。三维与二维读取同一执行器的步骤、进度和终态。
- 终端显示本步配方数量、实际库存和预占量。物料预占、步骤扣料、故障重试及持久化仍由原执行器处理，打开、关闭或旋转三维场景不改变任务或库存。
- 元数据沿原有 `task.acknowledged` HTTP/MQTT 事件上传，存入已有的步骤计划 JSON；云端公共订单响应新增 `production.robotView`，由原有 SSE 传送。无需数据库迁移，不新增关节帧上传或渲染服务。
- 手机在自己的浏览器渲染场景，仅接收步骤动作和配方用量，不接收设备库存、身份密钥或支付凭证。资源由云端同源 `/assets/robot/` 提供，无需访问终端 localhost。支付模拟逻辑保持原样。
- 暂停、重试等待、HOLD、失败及断连会停留在设备报告的位置；只在收到的进度之间平滑过渡，不根据动画自行宣布成功。旧终端没有视觉元数据的订单继续使用二维。

上线需同时更新终端代码与云端代码/静态资源，重启现有服务；新接单任务自动带上元数据。已有云端订单不会补写动作计划。此版本已做本地隔离实例联调，未部署或压测 VPS，也未在真实手机硬件上测帧率。

### 自定义配方

现有配方会根据步骤 ID、名称、动画提示和消耗物料自动映射工位。自定义步骤可以添加 `"robotActions": ["brew", "water"]` 明确顺序，允许 `cups / brew / water / milk / ice / syrup / lid / pickup / wait`。无法识别的步骤显示等待动作。特殊工艺请明确配置并检查场景。

视觉子动作压缩在各个实际步骤时长内，取杯、交接、出杯不额外延长后台制作时间；液面和机械运动是工艺示意，不是物理测量。

## 启动

macOS 双击项目根目录的 `start-robot-scene.command`，或执行：

```bash
./start-robot-scene.command
```

默认打开 `http://127.0.0.1:9120/robot-scene.html`。停止服务用 Ctrl+C；换端口可传 `--port 9121`。
只有 Python 标准库是运行时依赖；Three.js 已打包进仓库，无需 npm、外部 CDN 或联网。
静态服务器只开放 `coffee-terminal/web`，不提供实例配置、身份或密钥目录。

以下独立演示的播放与关节调试功能仅在 `robot-scene.html` 提供。生产同步弹窗没有播放、跳步或手动控制按钮。

## 操作

- 鼠标左键拖动旋转、右键拖动平移、滚轮缩放；触屏可拖动或双指操作。
- “透视 / 俯视 / 正视”切换相机，“↺”恢复当前预设视角。
- “工位”显示或隐藏工位标签；“坐标轴”显示两个末端工具坐标。
- 选择热拿铁、美式咖啡或香草拿铁，开始 / 暂停演示，速度可选 0.5×、1×、2×、4×。
- 点击流程步骤或拖动进度条会暂停并跳转；“下一步”跳到下一工艺阶段。
- “复位”恢复空杯、无盖、初始关节姿态；“再次演示”开始新一轮。
- “关节调试”会复位演示，然后可选择左右臂，单独调整 J1–J6；再次开始演示会退出调试。
- 页面切到后台时自动暂停。空格键可播放 / 暂停，表单控件获得焦点时不拦截空格。

## 场景与坐标

以米为单位，Y 轴竖直向上，顾客在 +Z 方向；桌面约 4.35m × 2.45m，高 0.94m。
尺寸为流程展示布局，不代表完成了紧凑型商用设备的机械设计。

| 工位 | 布局与作用 |
| --- | --- |
| 01 取杯 | 左侧杯架与前方单杯定位托盘 |
| 02 咖啡萃取 | 后排左侧，左臂持杯对准出口 |
| 03 热水 | 后排偏左，美式配方使用 |
| 04 双臂交接 | 中央定位托盘，左臂退出后右臂进入 |
| 05 鲜奶 | 后排偏右，右臂持杯接料 |
| 06 糖浆 | 后排右侧，香草拿铁配方使用 |
| 07 封盖 | 右侧压盖机构，夹爪退出后压盖 |
| 08 成品取杯 | 前侧右方，成品落杯后机械臂回位 |
| 09 冰块 | 左后方，冰饮配方使用 |

两台机械臂各有六个串联旋转关节，轴顺序为 Y / Z / Z / Y / Z / Y。肩部偏置 0.24m，上臂 0.66m，前臂 0.62m，末端偏置 0.24m。采用程序化连杆、关节壳体、夹爪、局部线缆和安装底座，无第三方机械臂模型资产。

演示采用解析逆运动学保持夹持杯竖直，动作路径显式定义为搬运、工位前方进退、夹持、释放和加工。
双臂通过定位托盘交接，没有同时持杯。灌注液面、杯盖、封盖压头与流程时间线同步。

## 代码与构建

```bash
npm ci
npm run build:scene
# 同步到相邻的 coffee-cloud-mvp/public/robot
npm run sync:cloud-scene
npm test
```

- `web/robot/kinematics.mjs`：尺寸、关节限制、解析逆运动学。
- `web/robot/sequence.mjs`：工位、演示配方、可确定性跳转的动作时间线。
- `web/robot/models.mjs`：真实三维几何、材质、机械臂层级和工位模型。
- `web/robot/scene.mjs`：相机、光照、渲染、模型状态映射和资源释放。
- `web/robot/app.mjs`：独立演示控制面板与播放状态。
- `robot_view.py`：从真实执行配方生成公开视觉元数据。
- `web/robot/live-plan.mjs`：将真实步骤编译为工位动作。
- `web/robot/live-snapshot.mjs`：终端、手机快照与过期状态过滤。
- `web/robot/live-viewer.mjs` / `integration.mjs`：只读渲染与延迟加载弹窗。
- `web/robot-live.bundle.js` / `robot-integration.bundle.js` / `robot-live.css`：两端同步的生成资源。
- `web/robot-scene.html` / `.css`：独立响应式界面。
- `web/robot-scene.bundle.js`：生成的离线包；修改源码后必须重新构建并一并提交。
- `web/robot/THREE-LICENSE.txt`：Three.js MIT 许可；npm 锁文件固定版本。

上面的 `web/` 均相对于 `coffee-terminal/`。

## 当前边界

这是运动学流程演示，没有真实碰撞求解、动力学、抓取力验证、流体物理或机器人安全认证。
手动关节模式只限制关节角度，不进行碰撞阻止；演示轨迹可达性不等于机械避碰验证。
演示配方与耗时独立于生产 JSON 配方，页面明确标识本地演示。

生产同步视图以 Python 和云端确认的状态为准，不能把前端动画完成当作生产成功。
